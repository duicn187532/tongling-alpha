# 架構與信任邊界

彤靈 Alpha 是單主機應用。Node 靜態前端程序只提供建置後的 React 檔案，並將 `/api` 轉送給獨立的 FastAPI 後端。SQLite 儲存專案、來源、工作狀態與配對 session。上傳文件、產生的圖表及輸出也保存在主機的 `data/`。Ollama 可在同一主機提供模型；外部 OpenAI 相容 API 須由主機管理者明確設定。

```text
主機瀏覽器 ──> 127.0.0.1:5173 前端 ── /api ──> 127.0.0.1:8000 管理 API
遠端瀏覽器 ──> ngrok HTTPS ──> 127.0.0.1:8002 客戶端前端 ── /api ──> 127.0.0.1:8001 受限 API
主機／受限 API ──知識 API──> 127.0.0.1:8765 公司檔案模擬服務 ──> company_files/
```

五個服務均只綁定 loopback。8000 是管理 API，8001 是不同程序的受限 API；兩者都不提供前端檔案。5173 是本機管理前端，8002 是客戶端前端，8765 是公司檔案模擬 API，ngrok 只能指向 8002。瀏覽器對每種角色都使用單一同源網址，避免跨來源 Cookie 與 API 問題。使用者透過短期配對碼取得持久 session，各自只可讀寫自己建立的專案。主機共用知識庫依專案檢索政策提供；不要把機敏文件放入允許共享的範圍。

彤靈的核心是 PM 工作管理台：`/api/dashboard` 從本機專案、會議、需求、版本、變更與工作紀錄計算跨專案摘要；個人代辦保存在每案狀態中。它不依賴公司檔案服務、雲端搜尋或遠端模型。配對客戶端的總覽與代辦 API 仍通過專案擁有者檢查。首頁流程百分比來自需求起點、證據、需求確認、PRD 草稿和業務基準五個里程碑；AI 工作狀態另外呈現。IT 缺項查核在 PRD 預覽中是可開關的參考清單，不影響業務 Baseline；正式 IT 交付包仍需另外執行交付檢查。

技術設計的 AI 輸出只使用本案已連結且可檢索的來源段落，帶來源與段落 ID，並保留人工補正步驟。PRD 定版與 IT 交付另有版本與審閱檢查；使用者輸入的審閱者姓名目前不是組織身份驗證。工作狀態、檢索結果與模型 trace 會留在主機資料庫，不會由程式自動推送到 GitHub。

## 知識服務邊界

彤靈內建知識庫仍儲存在 `data/`，由主機管理文件、標籤、圖譜、索引及專案可見範圍。`company_file_server` 是獨立 FastAPI 程序，只讀取 `company_files/` 並自行建立記憶體索引；彤靈不直接存取該資料夾。它只監聽 `127.0.0.1:8765`，用來模擬真實公司的獨立文件服務，並非企業級文件管理系統。

連接器使用 `GET /health`、`GET /capabilities`、`POST /search`、`GET /evidence/{id}` 與 `GET /evidence/{id}/metadata`。管理頁另用 `GET /documents` 及 `POST /rescan` 顯示清單與要求重掃。其他公司服務只要提供相同契約，即可在主機設定其 API 網址與 Bearer 金鑰環境變數。公司服務的搜尋只收到查詢詞；除非使用者另外開啟相關分享選項，專案名稱、需求全文與本機文件段落不會送出。遠端命中仍標示來源、版本與相關分數，未經本案審核不得僅因來自公司服務就成為關鍵證據。服務斷線時檢索降級並記錄稽核，彤靈內建知識庫仍可用。

模擬服務可分類文件、圖譜／圖表檔及圖片。圖譜檔支援 `/graph/search`，原始檔由 `/files/{id}` 提供下載，安全的點陣圖片可由 `/preview/{id}` 預覽。Office、PDF、OpenDocument 與圖譜格式會擷取文字供關鍵字檢索；點陣圖片僅索引檔名、尺寸與可得的中繼資料，不會偽稱已理解圖像或執行 OCR。圖譜檔的文字搜尋也不等同完整圖關聯推理。只有主機管理頁提供原檔操作，遠端客戶端仍經受限 API 使用檢索片段。

客戶端只能透過受限 API 使用管理者允許的共用來源；設定、連線測試、文件清單及重掃只在主機管理頁。請勿將 8765 或管理入口公開到 ngrok。`company_files/`、`data/` 與任何連線金鑰都不進入版本庫。

此架構適合個人或小團隊在可信任主機上試用；公開網路使用須啟用受限入口、保持主機更新，並依實際用途評估組織身份、備份、權限與稽核要求。
