# 部署、啟動與停止

本版提供 Windows 一鍵啟動。需求是 Python 3.12、Node.js 22.12 以上（含 npm）、可寫入的安裝資料夾。Ollama、ngrok 與公開搜尋 API 都是選用，不影響預設離線規則模式的啟動。首次安裝需連網下載 Python／Node 依賴，建立圖表時可能需要 Mermaid Chromium。

## 本機主機

1. 下載原始碼或解壓發行包，放到非系統目錄。
2. 雙擊 `start.cmd`。第一次啟動可能花數分鐘安裝依賴、建置前端及執行資料庫遷移。
3. 開啟 `http://127.0.0.1:5173`。前端、後端與公司檔案模擬服務分別在三個命令視窗顯示即時日誌；後端 `http://127.0.0.1:8000/api/health` 應回傳 `status: ok`、`gateway: false`。
4. 雙擊 `stop.cmd` 可關閉前端、後端與本套件啟動的客戶端通道。

若 8000 已被其他程序占用，啟動腳本會停止並提示，不會覆蓋資料。修改前端程式後重新啟動會重新建置，不會沿用過期畫面。預設執行資料位於 `data/` 與 `company_files/`；自訂專用資料夾可能位於其他位置，請連同它一起備份。**先關閉主機再備份 SQLite**；升級前請保留一份可還原備份。還原時先關閉系統，再將備份放回原位置。

## 公司檔案服務器與內建知識庫

`start.cmd` 同時啟動獨立的公司檔案模擬服務，另有一個即時日誌視窗。首次啟動且 `company_files/` 為空時，服務會複製兩份虛構範例文件。可把公司的測試文件放入 `company_files/`，在主機設定 → 知識來源按「連接本機模擬服務並啟用混合檢索」，再用「重新掃描公司資料夾」與「試查」驗證。支援 UTF-8 文字、Markdown、CSV、JSON／JSONL、YAML、SQL、PDF、DOCX、PPTX、XLSX、OpenDocument（ODT／ODS／ODP）、圖譜／圖表資料（GraphML、GEXF、GML、Cytoscape JSON、Mermaid、DOT、draw.io、SVG、VSDX）及常見點陣圖片。Office 與圖譜可搜尋擷取文字；圖片可預覽原圖，但只搜尋檔名、尺寸與中繼資料，不含 OCR。未知格式會作為可下載的附件列出，只索引檔名，不解析內容。檔案超過 30 MB、無法解析或符號連結會跳過，錯誤會顯示在管理頁。真實文件與自動產生的 `company_files/` 均被 Git 忽略。原有內建知識庫繼續在 `data/`，可由同頁進入文件、圖譜與檢索管理。

模擬服務可單獨以 `file-server.cmd` 啟動，`stop-file-server.cmd` 停止；`stop.cmd` 會一併關閉。健康檢查網址為 `http://127.0.0.1:8765/health`。若公司已有相容文件 API，在「設定其他公司 API」填 HTTPS 網址；金鑰放在主機環境變數，介面只填變數名稱。連線保存後先測試，再啟用該服務與工作空間的遠端查詢。主機只查詢相關片段，不會整批同步公司文件；此本機模擬服務沒有企業身份管理，不應對外公開。

## 分享受限客戶端

在主機安裝 ngrok 並於本機終端機執行 `ngrok config add-authtoken <權杖>`；權杖不要放入儲存庫。之後雙擊 `client.cmd` 即可啟用分享；主機尚未啟動時會先啟動主機。它會啟動 8001 受限 API 與 8002 客戶端前端、檢查健康狀態、建立或接續指向 8002 的 ngrok HTTPS 通道，並在主機顯示配對碼。兩個服務及 ngrok 各有自己的命令視窗與即時日誌。只需關閉分享時雙擊 `stop-client.cmd`；主機可繼續使用。

客戶端腳本將程序 ID 與公開網址記在被 Git 忽略的 `data/`，停止時只終止此安裝資料夾啟動的對應程序。若程序記錄不符，腳本會拒絕停止，避免誤關其他服務。通道目標必須是 8002，不能是 8000、8001 或 5173；不要把管理端接到任何公網反向代理。

## 模型與搜尋

預設 `mock` 是標示清楚的離線規則模式。若要使用真實 AI，請自行安裝 Ollama 與模型，或在主機環境設定 `OPENAI_API_KEY` 後由主機設定頁選擇 OpenAI 相容提供者。公開同業搜尋可用免金鑰 Google News RSS；Tavily／Brave 金鑰只由主機環境變數 `TAVILY_API_KEY`／`BRAVE_SEARCH_API_KEY` 讀取。所有服務金鑰都不應放在程式碼、設定匯出或 issue 中。

## 故障排除

- 啟動視窗出現安裝或建置錯誤：先確認 Python、Node/npm 版本與網路，再重新執行 `start.cmd`。
- 8000／8001／8002／5173 已使用：確認是否已有彤靈程序，或用 `stop.cmd` 停止本資料夾的程序；不要直接終止不明程序。
- 客戶端無法配對：確認 8001 API、8002 前端及 ngrok 通道都健康，並在主機取得新的配對碼。
- AI 沒反應：先在主機設定頁測試連線與實際生成；檢查模型是否已下載、Ollama 是否啟動，工作卡是否顯示失敗或等待。

## 20 人展示與佇列

主機「設定 → 展示併發」可調整模型、Agent、PRD、檢索並行量、等待上限、每人上限與逾時，並查看活躍 Session、排隊／執行／失敗數與可用的 GPU 指標。建議先以模型 2、PRD 1、檢索 4、待處理佇列 40、每人 3 項測試；效能取決於實際模型與主機記憶體。工作及配對 Session 保存在本機資料庫，重開頁面可查看自己的工作；主機服務重啟後，執行中的 Agent 需從檢查點重新提交。

主機設定「伺服器／客戶端連線」可切換正式模式（配對碼，預設）與展示模式（免配對碼，每個瀏覽器自動取得 8 小時的獨立 Session）。展示模式預設只接受區域網路訪客，請用 `client-lan.cmd` 啟動；切回正式模式會立即中止所有展示 Session，已配對裝置不受影響。佇列與專案隔離在兩種模式下一樣生效。

可重複的隔離壓測：在 `backend/` 執行 `..\.venv\Scripts\python.exe benchmarks\demo_queue_load.py --sessions 20`。它使用暫存資料庫與模擬模型，量測 20 個 Session 的混合工作、取消／恢復與跨 Session 隔離；結果不能代表實際 Ollama 的 20 人生成容量。
- 資料庫遷移失敗：不要刪除 `data/`；保留錯誤訊息與備份後再排查。
